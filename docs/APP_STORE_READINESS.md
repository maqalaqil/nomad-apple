## Review-sensitive behavior

- Imported Kolibri HTML5 packages execute JavaScript in WebKit and can communicate with a bounded progress bridge. Determine how Apple guidelines 2.5.2 and 4.7 apply to this course-player behavior, document the allowed content and bridge, and implement any applicable consent/index/age restrictions. This is a review question, not a prediction of rejection. [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).
- Drug Reference presents imported source-label text; it must not be described as validated treatment advice or a clinical interaction checker. Explain its source/date handling and current limitations to reviewers. Imported models and generated answers likewise require accurate capability claims.
- Large downloads, user-selected content, and device storage vary. Provide a review path with small licensed content; reviewers should not need to download hundreds of gigabytes to exercise the app. Retest pause/relaunch, low storage, background completion, import failure, backup/restore, and data preservation in the release configuration.
- Verify offline reading, maps, supported courses, and inference after preparation with networking actually disabled. Retain the distinction between on-device execution and independently verified network isolation. Do not advertise M1-specific performance or complete offline feature coverage without corresponding tests.

## Distribution sequence

1. Resolve licensing and implement the privacy, identity, icon, and export-compliance requirements above. Keep developer signing files, private diagnostics, user content, and model/archive downloads out of Git.
2. Use an active Apple Developer Program membership and an authorized App Store Connect role to create the app record. Archive and validate the Release build; inspect its embedded frameworks, licenses, privacy manifest, icon, and absence of debug fixtures. Upload to App Store Connect only after these gates pass. A local development provisioning profile is not evidence of distribution readiness. [Upload workflow](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds).
3. Run internal TestFlight testing, then external beta review/testing as appropriate. Exercise clean installation, upgrades, restoration, accessibility, actual offline operation, and the supported iPad hardware range. Fix release blockers without erasing user data.
4. Complete metadata, privacy answers, age/content rights, support and review notes; select the validated build and submit it to App Review. Approval remains Apple's decision. Publishing this repository does not publish the app on the App Store.
